# interview-video：YouTube 访谈 → 中文访谈长文

```
/interview-video <YouTube链接> [slug] [--auto] [--deep-polish]
```

- `--auto`：全自动，提纲处不停；提纲照样写进素材包，成稿后一并汇报
- `--deep-polish`：润色时，盲读挑出的段落和开头、结尾改用 adversarial-polish（更贵、更细）
- `slug`：这期的英文短名，默认 `受访者_节目_期号`；拿不到期号或嘉宾名时，用 `频道_主题关键词`
- 用户用中文说"全自动""深度润色"，等同于上面两个开关

**目录约定**：项目根目录是存放访谈长文的目录（下文称"根"），脚本在 `根\tools\`；每期的工作目录是 `根\素材\<slug>\`；成稿是 `根\<slug>_访谈长文.md`，配图在 `根\<slug>_访谈长文_assets\`。

**开工前**读一遍 `references\历史错误清单.md`，只读这一次。它记录了以往长文被用户指出、导致返工的问题，下面每一步都有对应的防线。

## 先定模式：按访谈时长

| 时长 | 模式 | 为什么 |
|---|---|---|
| 30 分钟以内 | **直做模式**：主对话自己分析、写作、润色、核对；只有盲读和配图交给子 agent | 逐字稿只有几千 token，留在主对话里几乎不花钱。拆成子 agent 反而更贵、更慢：每个子 agent 都要重读规则，还有固定开销，只能一个接一个等 |
| 30 分钟以上 | **分工模式**：主对话只调度，重活交给子 agent | 逐字稿动辄几万 token，留在主对话里，之后每次调用都要重发一遍 |

实测数据：一段 11 分钟的片段，用分工模式跑了 24 分钟，派了 7 个子 agent，输入约 1,070 万 token；一段 24 分钟的访谈用直做模式，约 10 分钟，输入约 160 万 token。两篇的质量评分相近（6.5 对 7）。

两种模式的产物和三道闸门完全一样，断点续跑的规则也一样。

## 产物清单（也是断点续跑的依据）

已存在的产物直接跳过，从缺失的那一步接着做。

| 步骤 | 产物（都在 `素材\<slug>\` 下，成稿和配图除外） |
|---|---|
| 1 下载 | `source.info.json`、`source.*.json3`、`video.mp4`、`transcript.md` |
| 2 分析 | `分析素材包.md`、`译名表.md` |
| 3 写作 | `chapters\NN.md`（分工模式另有 `chapters\NN.brief.md`） |
| 4 盲读与润色 | `盲读\NN.json` 或 `盲读挑刺.json`、`润色记录*.json` |
| 5 核对 | `核对\覆盖表*.csv`、`核对\审查*.md`、`核对\修订记录*.json` |
| 6 配图 | `配图计划.json`、`根\<slug>_访谈长文_assets\` |
| 7 终稿 | `文末附注.md`、`根\<slug>_访谈长文.md`、`lint.json` |

## 第 1 步：下载与逐字稿

先查标题、频道和时长，用来起 slug、定模式：

```powershell
根\tools\yt-dlp.exe --no-playlist --skip-download --print "%(title)s | %(channel)s | %(duration_string)s | %(upload_date)s" "<链接>"
powershell -ExecutionPolicy Bypass -File 根\tools\fetch.ps1 -Url "<链接>" -Slug "<slug>"
```

- 失败时依次尝试：`根\tools\yt-dlp.exe -U` 更新；加 `-CookiesFrom chrome`；先用 `-SkipVideo` 拿到字幕开始写作，配图前再下载视频
- 非英文访谈：加 `-Lang <语言代码>`

## 第 2 步：分析 → 停一次

按 `interview-analysis` 技能产出 `分析素材包.md` 和 `译名表.md`。格式要求（后面的脚本按格式解析）：
- 提纲每章一行加粗标题加时间范围：`**一、手机关着屏，也一直在喊"我在这里"** [00:00:00–00:07:59]`
- 要有标题含"金句"的一节，和标题含"原话清单"的一节
- 章节粒度：每章 5–15 分钟。30 分钟以内的片段一般 2–4 章，不要切成两三分钟一章

- **直做模式**：主对话自己通读逐字稿完成分析。
- **分工模式**：派 1 个分析子 agent（模板见文末"分工模式"），主对话只看它回报的提纲。

完成后（`--auto` 时不停），把提纲和译名表中拿不准的条目给用户看，等确认或修改。用户要改，就直接编辑素材包里对应的提纲行。

**分析一完成，立刻在后台派配图子 agent**，和写作、润色、核对并行进行，见第 6 步。

## 第 3 步：写作

**直做模式**：主对话读一次 `interview-writing` 技能、`writing-style` 技能和 `interview-writing\references\写作卡.md`，然后按提纲把各章一口气写完，存为 `chapters\NN.md`。写法：先想清楚每段在说什么，再照中文要点写，不逐句对照英文翻译。第 1 章前面加文章开头，最后一章后面加结尾。**不写文末附注和复核说明**，那是第 7 步的事。全部写完后，用一条命令检查所有章节：

```powershell
Get-ChildItem 根\素材\<slug>\chapters\[0-9][0-9].md | ForEach-Object { python -P 根\tools\lint_zh.py $_.FullName --max 10 }
```

**分工模式**：见文末。

## 第 4 步：盲读挑刺与润色

### 4a 盲读（两种模式都要隔离）

盲读者必须没看过英文，所以一定交出去：
- **Claude Code**：派 1 个盲读子 agent 读全部章节（分工模式按章分批），prompt：

```
你负责盲读 {根}\素材\{slug}\chapters\ 下第 {NN}–{MM} 章的正文（NN.md）。
审读要求见 {根}\tools\blind_read_prompt.md（里面说正文在 <stdin> 块中，在这里指的就是这几个章节文件）。
只读这几个章节文件和这份提示词；不要读 brief、transcript、素材包或任何英文材料。
每章的结果写进 {根}\素材\{slug}\盲读\NN.json（JSON 数组，没有问题就写 []）。回报：每章挑出几处。
```

- **Codex**：运行 `powershell -ExecutionPolicy Bypass -File 根\tools\blind_read.ps1 -Dir 根\素材\<slug>`。默认模型 `gpt-5.6-sol`，报"模型不支持"时用 `-Model` 换一个。

### 4b 润色

按 `references\润色卡.md` 执行。直做模式由主对话润色，分工模式交给润色子 agent。要点：
- 逐条判断盲读意见，合理的改，不合理的写明理由；受访者自己的比喻、例子，一律只改措辞不删
- 改完逐条核对"原话清单"，每一项都还在正文里
- 第 1 章开头、最后一章结尾必须精修
- 改动记入 `润色记录.json`（直做）或 `润色记录_NN.json`（分工）

**直做模式要多防一点**：主对话读过英文，润色时容易被英文句式带着走。所以润色时先通读中文、只看中文改，改完再用盲读的意见检查一遍。

**`--deep-polish`**：润色完成后，把盲读挑出的段落连同开头、结尾交给 `adversarial-polish`，用快速模式（2 位评委，最多 2 轮）。批评者、改写者、综合者、评委都由主对话逐个派子 agent，每个角色只拿文件路径。任务描述：

```
这是一篇英文访谈的中文实录整理稿（第 NN 章）。读者是不看原视频、英文不一定好的中文读者。
目标：读起来像中文原创报道，没有翻译腔，节奏自然，问答清楚。
硬约束：①不得增删任何信息点、数字、人名、限定词；②不得软化或强化受访者的表态，不得对受访者作评价；
③争议、尖锐内容必须原样保留，不得以"冗长""敏感"为由建议删减；④编者注只补背景，不做价值判断；
⑤每章最多 2 条双语金句；⑥"原话清单"里受访者的比喻、例子和金句不得删除。风格依据 writing-style 技能和写作卡。
```

评委总是选删得最多的版本时，停用深度润色，并在复核说明里写明原因。

## 第 5 步：忠实与偏向核对（对照英文）

按 `references\核对卡.md` 执行。直做模式由主对话核对，分工模式交给核对子 agent。产出：
- `核对\覆盖表.csv`（分工模式每份负责的章节各一份 `覆盖表_NN.csv`）：逐字稿每一段都登记
- `核对\审查.md`、`核对\修订记录.json`

然后运行：

```
python -P 根\tools\coverage.py 根\素材\<slug>\transcript.md "根\素材\<slug>\核对\覆盖表*.csv"
```

ERROR 必须为 0。排除超过全片 8%，或连续排除超过 3 分钟的，逐句复核。

## 第 6 步：配图（1 个子 agent，第 2 步之后就在后台开始）

```
你负责为 {根}\素材\{slug} 这期访谈配图。先读 <技能目录>\interview-video\references\配图卡.md，照着做。
视频：{根}\素材\{slug}\video.mp4；内容依据：{根}\素材\{slug}\分析素材包.md 的提纲（正文还在写，不要等正文）。
anchor 先留空，在 reason 里写清这张图配哪段内容、哪一章。
回报：选了几张、各配哪章哪段内容、哪些规则没能满足及原因。
```

正文定稿后，主对话（分工模式交给终稿审查子 agent）给每张图的 `anchor` 填上正文中对应段落的一段原文。插图时 `frames.py insert` 不报"找不到锚点"，才算配好。

## 第 7 步：终稿

1. 写 `文末附注.md`，包含两节：
   - "## 文末附注"：事实核查和背景补充，受访者说法与公开资料有出入的在这里说明，正文不插话；核对时记在 `核对\附注素材.md` 里的内容也汇总进来
   - "## 复核说明"：数字来自 `report.py` 的输出和审查记录：改了几处、盲读挑出几处、不采纳几条、核对修订几处、排除了多少分钟、配图几张、未解决项和推断之处；最后附原始视频链接
   
   这一步还要做两件事：按项目规则（CLAUDE.md 或 AGENTS.md）通读全文，做一遍偏向审查；核查编辑自己写的事实，包括开头、编者注、结尾里的日期、年龄、任期、"X 年前"、头衔。
   - 直做模式：主对话自己做
   - 分工模式：派 1 个终稿审查子 agent，模板见文末
2. 合并、插图、汇总：

```
python -P 根\tools\merge.py 根\素材\<slug> 根\<slug>_访谈长文.md
python -P 根\tools\frames.py insert 根\<slug>_访谈长文.md 根\素材\<slug>\配图计划.json
python -P 根\tools\report.py 根\素材\<slug>
```

3. **三道闸门**，全部通过才算完成：

```
python -P 根\tools\lint_zh.py 根\<slug>_访谈长文.md --full --json 根\素材\<slug>\lint.json
python -P 根\tools\coverage.py 根\素材\<slug>\transcript.md "根\素材\<slug>\核对\覆盖表*.csv" --article 根\<slug>_访谈长文.md
```

- lint：ERROR 为 0（含开头和结尾的链接、复核说明），破折号每千字不超过 4 个
- coverage：ERROR 为 0；被标为偏薄的章节，逐段对照逐字稿
- 配图：`report.py` 显示"未核对 0 张"且没有缺锚点；`frames.py insert` 没有报"找不到锚点"

不通过就改对应的章节文件（不要直接改成稿，成稿会重新合并），再从第 2 条重来。

4. **向用户报告**：成稿路径、字数、配图数、三道闸门的结果、审查中修订的要点、`report.py` 列出的改动最大的 5 处（改前和改后，方便几分钟内抽查润色方向）。结论必须有数据支撑，不写"通篇没有其他问题"这类无法验证的话。`--auto` 跳过了提纲确认时，附上提纲和章节划分的理由。

## 分工模式（30 分钟以上）

### 主对话怎么干活

主对话只负责调度：运行脚本、派子 agent、看脚本摘要和子 agent 的简短回报、在提纲处和用户沟通。

- **主对话不读**：`transcript.md`、章节正文、成稿全文、图片、`tools\` 下的脚本源码。例外：用户追问原话时，用 rg 按时间点查一小段；脚本报错、看不懂报错时，可以读出错脚本的源码。
- **子 agent 只读自己那张卡**：写作读写作卡（已打包进材料），润色读润色卡，核对读核对卡，配图读配图卡。不读本技能文件，也不读整份历史错误清单。
- **子 agent 一次调用干完一批活**：比如先把几章都写完，再用一条命令一起跑 lint。每次调用都要重发整个上下文，调用次数越少越省。
- Claude Code 用 Agent 工具（general-purpose），Codex 用子代理。prompt 里只给文件路径和任务，不复制主对话的上下文。回报控制在 20 行以内，正文不要贴回来。子 agent 不能再派子 agent。
- 长命令一次等到结束，不要反复查询后台进程。

子 agent 数量：

| 时长 | 写作 / 润色 / 核对 / 盲读 |
|---|---|
| 30–90 分钟 | 每 3–4 章 1 个 |
| 90 分钟以上 | 每 2–3 章 1 个 |

分析、配图、终稿审查始终各 1 个。

### 分析子 agent

```
你负责分析一期访谈，产出写作素材包和译名表。
先读：<技能目录>\interview-analysis\SKILL.md，严格执行。
输入：{根}\素材\{slug}\transcript.md（通读全文）
输出：{根}\素材\{slug}\分析素材包.md、译名表.md
格式要求：提纲每章一行加粗标题加时间范围，例如 **一、标题** [00:00:00–00:07:59]；要有标题含"金句"和"原话清单"的两节。
完成后只回报：每章的标题、时间范围和 3–5 个要点；译名表中拿不准的条目；标了【说话人存疑】的地方。不要贴素材包全文。
```

### 写作子 agent

主对话先打包材料，把写作卡一起放进去：

```
python -P 根\tools\pack_chapter.py 根\素材\<slug> --card <技能目录>\interview-writing\references\写作卡.md
```

```
你负责写一篇中文访谈长文的第 {NN}–{MM} 章。
每章的规则和材料都在 {根}\素材\{slug}\chapters\NN.brief.md 里：最前面是写作卡，后面是提纲、候选金句、逐字稿片段、上一章结尾、译名表。读这一个文件就够，不要再读别的。
写法：先读完本章英文，想清楚每段在说什么，再照提纲的中文要点写；不逐句对照英文翻译。第 1 章前面加文章开头，最后一章后面加结尾。不写文末附注和复核说明。
把分到的几章都写完，保存为 chapters\NN.md，再用一条命令一起检查：
Get-ChildItem {根}\素材\{slug}\chapters\[0-9][0-9].md | ForEach-Object { python -P {根}\tools\lint_zh.py $_.FullName --max 10 }
ERROR 必须改到 0；WARN 逐条处理（改，或在文件末尾的 HTML 注释里说明保留理由）。
回报：每章字数、lint 结果、你觉得写得最不顺的一处。
```

并行写作时，后一章可能看不到前一章的结尾，章节衔接留给润色处理。

### 润色子 agent

```
你负责润色 {根}\素材\{slug}\chapters\ 下第 {NN}–{MM} 章（NN.md）。
只读：<技能目录>\interview-video\references\润色卡.md；分析素材包.md 中"原话清单"和"金句"两节；盲读意见 盲读\NN.json 或 盲读挑刺.json 中本章的条目；上一章 NN.md 的最后一段（处理衔接）。
不要读 brief、transcript 或任何英文材料。照润色卡执行；改动记入 润色记录_NN.json，疑问记入 润色疑问_NN.md。
回报：每章改了几处、不采纳几条、留了几条疑问、lint 结果。
```

### 核对子 agent

```
你负责核对 {根}\素材\{slug}\chapters\ 下第 {NN}–{MM} 章。
只读：<技能目录>\interview-video\references\核对卡.md；每章的正文 NN.md 和材料 NN.brief.md（里面有英文逐字稿）；润色疑问_NN.md（如果有）。
照核对卡执行，产出 核对\覆盖表_NN.csv、核对\审查_NN.md、核对\修订记录_NN.json。brief 开头那段逐字稿属于上一章，不用登记。
回报：每章修订了几处、排除了哪些时间段。
```

### 终稿审查子 agent

```
你负责一篇访谈长文的终稿审查。先运行：
python -P {根}\tools\merge.py {根}\素材\{slug} {根}\{slug}_访谈长文.md
python -P {根}\tools\report.py {根}\素材\{slug}
再读：项目根目录的 CLAUDE.md 或 AGENTS.md、成稿全文、核对\审查_*.md、核对\附注素材.md（如果有）、配图计划.json。
1. 偏向审查：编者注、转场句、小标题有没有替读者下判断，有没有暗中贬低受访者
2. 核查编辑自写的事实：开头、编者注、结尾里的每个日期、年龄、任期、"X 年前"、头衔；正文和编者注里的同一年份要一致
3. 给配图计划里 anchor 为空的图，填上正文中对应段落的一段原文
4. 写 {根}\素材\{slug}\文末附注.md（"## 文末附注"和"## 复核说明"两节，最后附原始视频链接）
需要改正文的，改 chapters\NN.md，不要直接改成稿。回报：改了什么、附注几条。
```

## 脚本速查

用法都在这里，不要为了查用法去读脚本源码。

| 脚本 | 用法 | 作用 |
|---|---|---|
| `fetch.ps1` | `-Url <链接> -Slug <slug> [-SkipVideo] [-CookiesFrom chrome] [-Lang en]` | 下载元数据、字幕、720p 视频，生成 transcript.md |
| `pack_chapter.py` | `<素材目录> [章号 ...] [--card 卡片.md ...]` | 生成每章的写作材料 `chapters\NN.brief.md`，可把规则卡放在最前面 |
| `lint_zh.py` | `<文件> [--full] [--json 输出] [--max N]` | 中文质量检查，有 ERROR 时退出码为 1 |
| `blind_read.ps1` | `-Dir <素材目录> [-Chapters 01,02] [-Model ...]` | 用 codex exec 逐章盲读（Codex 用） |
| `coverage.py` | `<transcript.md> <覆盖表...> [--article 成稿]` | 覆盖检查；可传多个表或通配符；章节列填标题或章号都行 |
| `frames.py` | `sheet <视频> <目录> --start --end --step` / `grab <视频> <计划> <assets>` / `insert <成稿> <计划>` | 缩略图拼板、取原帧、插图 |
| `merge.py` | `<素材目录> <成稿>` | 合并各章和文末附注；已有成稿时备份为 `.上一版.md` |
| `report.py` | `<素材目录> [--top 5]` | 汇总改动、不采纳、盲读、配图记录，列出改动最大的几处 |
