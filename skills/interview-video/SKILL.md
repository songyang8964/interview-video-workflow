# interview-video：YouTube 访谈 → 中文访谈长文

```
/interview-video <YouTube链接> [slug] [--deep-polish]
```

- 项目根目录：你存放访谈长文的目录（下文简称"根"）；脚本在 `根\tools\`
- `slug` 默认为 `受访者_节目_期号`（英文与下划线），例如 `Rupert_Lowe_JoeRogan_2524`
- 每期的工作目录：`根\素材\<slug>\`；所有中间产物都落盘，中断后从缺失的那一步继续

## 产物清单（也是断点续跑的依据）

| 步骤 | 产物（工作目录内，成稿除外） | 已存在则跳过 |
|---|---|---|
| 0–1 | `source.info.json`、`source.*.json3`、`video.mp4`、`transcript.md` | ✓ |
| 2 | `分析素材包.md`（含提纲） | ✓ |
| 3 | `chapters\NN.md`（每章一个文件） | 按章跳过 |
| 4 | `chapters\NN.md` 已润色、`润色记录.json` | 按章跳过 |
| 5 | `完整性与偏向审查.md` | ✓ |
| 6 | `配图计划.json`、`根\<slug>_访谈长文_assets\` | ✓ |
| 7 | `根\<slug>_访谈长文.md`、`lint.json` | — |

## 第 0–1 步：下载与逐字稿（脚本，不耗模型）

```powershell
powershell -ExecutionPolicy Bypass -File 根\tools\fetch.ps1 -Url "<链接>" -Slug "<slug>"
```

- 失败时依次尝试：`yt-dlp -U` 更新 yt-dlp；加 `-CookiesFrom chrome`；字幕先拿到，用 `-SkipVideo` 先写作，配图前再下载视频
- 非英文访谈：加 `-Lang <语言代码>`
- 自动字幕没有标点，也没有说话人标注。分析时根据上下文判断谁在说话；拿不准的，在素材包里标【说话人存疑】，第 5 步核对

## 第 2 步：分析 → ⏸ 停一次

按 `interview-analysis` 技能执行，输入为 `transcript.md`。补充要求如下：
- 每个信息点、金句、追问都标注 `[HH:MM:SS]` 时间戳
- 提纲中的"回复要点"用**中文意群**写，不抄英文句子；英文原话只出现在"可用金句"里
- 提纲中每章都写明对应的**时间范围**（`[起–止]`），第 3、5 步按它切逐字稿
- 素材包控制在逐字稿中文篇幅的 1/3 以内，不要写成第二份逐字稿

**完成后停下来**，给用户看提纲（章节标题、时间范围、每章 3–5 个要点），等用户确认或修改后再继续。这是唯一的人工节点；之后的步骤一路跑完，除非遇到错误。

## 第 3 步：逐章写作

开写前读：`interview-writing` 技能、`writing-style` 技能、`interview-writing\references\写作卡.md`。

每章的输入**只有三样**：
1. 该章提纲和素材（从素材包里截取）
2. 该章时间范围内的逐字稿片段（只用来核对数字、人名和细节）
3. 上一章的最后一段（用于衔接）

写法：先读完该章英文，想清楚每段在说什么，再按中文要点来写，**不逐句对照英文翻译**。
每章写进 `chapters\NN.md`，第 1 章前面加文章开头，最后一章后面加结尾。

**并行写作（章节 ≥ 6 时）**：每 2–3 章派一个子 agent，prompt 使用下方的"子 agent 模板"。主 agent 只负责调度和检查，不把全文读进自己的上下文。

### 子 agent 模板（写作）

```
你负责写一篇中文访谈长文的第 {NN}–{MM} 章。
先用 Read 读这三个文件，严格执行：
- <技能目录>\interview-writing\SKILL.md
- <技能目录>\interview-writing\references\写作卡.md
- <技能目录>\writing-style\SKILL.md
然后读本章材料：
- 提纲与素材：{素材包路径} 中"{章节标题}"一节
- 逐字稿：{transcript.md 路径} 中 [{起}] 到 [{止}] 的段落（用 Grep/Read 的 offset 定位，不要通读全文）
- 上一章结尾：{上一章文件路径} 的最后一段
写完保存到 {chapters\NN.md}，再运行：python -P 根\tools\lint_zh.py {chapters\NN.md}
ERROR 必须改到 0；WARN 逐条处理（改，或在文件末尾的 HTML 注释里说明保留理由）。
返回：每章字数、lint 结果，以及你认为素材里写得最不顺的一处。
```

## 第 4 步：中文润色（只看中文）

逐章执行，**润色者不读英文**：
1. 运行 `python -P 根\tools\lint_zh.py chapters\NN.md --json chapters\NN.lint.json`
2. 读 `references\翻译腔对照表.md`，然后以中文编辑的眼光通读本章：先处理 lint 提示，再处理 lint 查不出的问题（抽象主语、搭配不当、节奏单调、段落衔接生硬）
3. **只改表达，不增删信息**。数字、人名、限定词、谁说的，一概不动
4. 每处改动在 `润色记录.json` 里记一条 `{chapter, before, after, reason}`

**深度润色（`--deep-polish`，或用户点名要求时）**：对开头一章，以及 lint WARN 密度最高的 2–3 章运行 `adversarial-polish`。使用快速模式（2 位评委，最多 2 轮），任务描述如下：

```
这是一篇英文访谈的中文实录整理稿（第 NN 章）。读者是不看原视频、英文不一定好的中文读者。
目标：读起来像中文原创报道，没有翻译腔，节奏自然，问答清楚。
硬约束：①不得增删任何信息点、数字、人名、限定词；②不得软化或强化受访者的表态，不得对受访者作评价；
③争议、尖锐内容必须原样保留，不得以"冗长""敏感"为由建议删减；④编者注只补背景，不做价值判断；
⑤每章最多 2 条双语金句。风格依据 writing-style 技能和写作卡。
```

如果评委总是选删减最多的版本，就停用深度润色，改回单 pass 润色，并在审查记录里写明原因。

## 第 5 步：忠实与偏向核对（对照英文）

逐章对照该章的逐字稿片段（可用子 agent 并行，每个子 agent 只拿一章的正文和对应逐字稿片段）：
- **完整性**：逐字稿中讨论超过 30 秒的每个话题，都要在正文中找到对应段落；具体例子、数字、人名、典故不可被概括掉。尤其警惕"这段太尖锐、太争议、差不多已经写到了"的念头
- **走样**：润色后的数字、限定词、说话人、语气强弱是否与原话一致
- **偏向**（`docs/项目规则.md`）：措辞对等；没有评判性措辞；编者注不做价值判断；事实核查放到文末附注
- **说话人**：素材包里标了【说话人存疑】的地方，逐一确认

结果写进 `完整性与偏向审查.md`：每章一节，列出每项结论（通过 / 已修订：位置和原因）。发现遗漏或走样就直接修改对应章节；修改后对该章重跑 lint。

## 第 6 步：配图

1. **粗筛**：`python -P 根\tools\frames.py sheet 素材\<slug>\video.mp4 素材\<slug>\sheets --start 0 --end <时长> --step 30`。先看全片联系表，找出现场全景、节目当场展示的屏幕材料（推文、图表、照片、地图、新闻画面）和场景切换。
2. **精筛**：只在候选时间点附近用 `--step 3` 再出一张局部联系表，确认最佳时刻。
3. **选 8–15 张**：开场现场全景 1 张；屏幕材料优先；受访者特写不超过 3 张，而且必须对应正文中的关键论述或情绪高点。不选闭眼、转场或模糊的画面，也不凭表情推断心理。
4. **写计划**：写入 `配图计划.json`，每项包含 `seconds, file, chapter, anchor（正文中一段原文）, before, alt, caption（以"（原视频 HH:MM:SS）"结尾）, reason, visual_check`。
5. **取图**：`python -P 根\tools\frames.py grab 素材\<slug>\video.mp4 素材\<slug>\配图计划.json 根\<slug>_访谈长文_assets`
6. **核对**：用 Read 打开每张原图，确认画面与图注、正文一致，把结果写进 `visual_check`。对不上就换时间点重新 grab。
7. 第 7 步合并全文之后，再运行 `frames.py insert` 插图。

## 第 7 步：终检与输出

1. 按顺序合并各章 `chapters\NN.md`，写入 `根\<slug>_访谈长文.md`，再运行 `frames.py insert <成稿> 配图计划.json`
2. 运行 `python -P 根\tools\lint_zh.py <成稿> --json 素材\<slug>\lint.json`：ERROR 必须为 0，破折号每千字 ≤ 4
3. 按 `docs/项目规则.md` 再做一遍**左翼偏向审查**（逐条检查编者注和转场句）
4. 文末附上：事实核查附注、原始链接，以及"复核说明"（润色改了多少处、审查修订了多少处、未解决项）
5. 向用户报告：成稿路径、字数、配图数、lint 结果、审查中修订的要点

## 节省 token 的规则（质量不打折）

质量取决于"每一步看对的材料"，不取决于"每一步都看全部材料"。

1. **能用脚本做的事不交给模型**：下载、字幕整理、分段、截图、画质判断、插图、格式和禁用词检查都由脚本完成，模型只看脚本的输出摘要。
2. **逐字稿只通读一次**：只在第 2 步通读全文。之后各步按时间范围用 Grep/Read 的 offset 读取对应片段，不再整篇读入。
3. **主 agent 的上下文保持轻量**：章节正文写在文件里。主 agent 只负责调度、看 lint 摘要、看子 agent 的简短回报，不把 10 万字的全文读进来。终检时也按章节逐段读。
4. **子 agent 只拿该看的材料**：规则文件 + 本章素材 + 本章逐字稿片段。规则文件放在 prompt 开头且内容固定，利于缓存复用。
5. **改动用 Edit 定点修改**：根据 lint 给出的行号精确修改，不重写整章，也不反复整篇重读。
6. **深度润色只用在刀刃上**：adversarial-polish 一章要跑 5–7 次子 agent，只用于开头和 lint 最差的 2–3 章；其余章节用单 pass 润色加 lint。
7. **看图先粗后细**：一张 40 格联系表约等于一张图的 token 成本；先 30 秒间隔看全片，再在候选点附近看 3 秒间隔，最后只打开选中的原图。
8. **素材包不写成第二份逐字稿**：篇幅控制在逐字稿的 1/3 以内，用中文要点加时间戳，后续步骤需要原话时再回逐字稿查。
9. **断点续跑**：产物已存在的步骤直接跳过；长视频可以分几次对话完成，新对话里说"继续 <slug>"即可。
10. **按步骤选模型**：写作和润色用最强的模型；第 5 步的覆盖核对可以交给较便宜的模型初筛，发现疑点再由主模型复核。
