# interview-video：YouTube 访谈 → 中文访谈长文

```
/interview-video <YouTube链接> [slug] [--auto] [--deep-polish]
```

- `--auto`：全自动，提纲处不停；提纲照样写进素材包，成稿后一并汇报
- `--deep-polish`：润色时，被挑出的段落改用 adversarial-polish（更贵、更细）
- `slug`：这期的英文短名，默认 `受访者_节目_期号`，例如 `Rupert_Lowe_JoeRogan_2524`
- 用户用中文说"全自动""深度润色"，等同于上面两个开关

**目录约定**：项目根目录是存放访谈长文的目录（下文称"根"），脚本在 `根\tools\`；每期的工作目录是 `根\素材\<slug>\`；成稿是 `根\<slug>_访谈长文.md`，配图在 `根\<slug>_访谈长文_assets\`。

**开工前**，主会话读一遍 `references\历史错误清单.md`，只读这一次。它记录了以往 13 篇长文被用户指出、导致返工的问题，下面每一步都有对应的防线。

## 主会话怎么干活

主会话只负责调度：运行脚本、派子 agent、看脚本摘要和子 agent 的简短回报、在提纲处和用户沟通。这样做一是省额度，二是保质量：主会话上下文短，规则不容易被冲淡，也不容易触发上下文压缩。

**主会话不读**这些内容：`transcript.md`、章节正文、成稿全文、图片、`tools\` 下的脚本源码。这些都交给子 agent 去读。有三个例外：
- 用户追问"原话是怎么说的"，用 rg 按时间点在逐字稿里查一小段；
- 提纲确认时，读子 agent 回报的提纲摘要；
- 脚本报错、看不懂报错信息时，可以读出错脚本的源码排查。

**派子 agent 的规矩**：
- Claude Code 用 Agent 工具（general-purpose）；Codex 用子代理。prompt 里只给文件路径和任务，不复制主会话的上下文，需要的材料由子 agent 自己读。
- 子 agent 的回报控制在 20 行以内：做了什么、产出在哪、有什么需要主会话决定的。正文不要贴回来。
- 子 agent 不能再派子 agent。需要多角色的环节（`--deep-polish`），由主会话逐个派。
- 长命令一次等到结束，不要反复查询后台进程的状态。

**子 agent 数量按访谈长度定**。每个子 agent 都有固定开销，短视频拆得太碎反而更费额度：

| 访谈时长 | 写作 / 润色 / 核对 | 盲读 |
|---|---|---|
| 40 分钟以内 | 各 1 个，负责全部章节 | 1 个 |
| 40–90 分钟 | 每 3–4 章 1 个 | 每 3–4 章 1 个 |
| 90 分钟以上 | 每 2–3 章 1 个 | 每 2–3 章 1 个 |

分析、配图、终稿审查始终各 1 个。

## 产物清单（也是断点续跑的依据）

已存在的产物直接跳过，从缺失的那一步接着做。

| 步骤 | 产物（都在 `素材\<slug>\` 下，成稿和配图除外） |
|---|---|
| 1 下载 | `source.info.json`、`source.*.json3`、`video.mp4`、`transcript.md` |
| 2 分析 | `分析素材包.md`、`译名表.md` |
| 3 写作 | `chapters\NN.brief.md`（写作材料）、`chapters\NN.md`（正文） |
| 4 盲读与润色 | `盲读\NN.json` 或 `盲读挑刺.json`、`润色记录_NN.json` |
| 5 核对 | `核对\覆盖表_NN.csv`、`核对\审查_NN.md` |
| 6 配图 | `配图计划.json`、`根\<slug>_访谈长文_assets\` |
| 7 终稿 | `文末附注.md`、`根\<slug>_访谈长文.md`、`lint.json` |

## 第 1 步：下载与逐字稿（主会话运行脚本）

```powershell
powershell -ExecutionPolicy Bypass -File 根\tools\fetch.ps1 -Url "<链接>" -Slug "<slug>"
```

- 失败时依次尝试：`根\tools\yt-dlp.exe -U` 更新 yt-dlp；加 `-CookiesFrom chrome`；先用 `-SkipVideo` 拿到字幕开始写作，配图前再下载视频
- 非英文访谈：加 `-Lang <语言代码>`
- 脚本最后会打印逐字稿的段数和词数，主会话据此判断访谈长度和子 agent 数量

## 第 2 步：分析（1 个子 agent）→ 停一次

子 agent 模板：

```
你负责分析一期访谈，产出写作素材包和译名表。
先读：<技能目录>\interview-analysis\SKILL.md，严格执行。
输入：{根}\素材\{slug}\transcript.md（通读全文）
输出：
- {根}\素材\{slug}\分析素材包.md
- {根}\素材\{slug}\译名表.md
格式要求（后续脚本按这个格式解析，必须遵守）：
- 提纲每章一行加粗标题加时间范围，例如：**一、手机关着屏，也一直在喊"我在这里"** [00:00:00–00:07:59]
- 素材包里要有标题含"金句"的一节，和标题含"原话清单"的一节（见技能说明）
完成后只回报：每章的标题、时间范围和 3–5 个要点；译名表中拿不准的条目；标了【说话人存疑】的地方。不要贴素材包全文。
```

主会话收到回报后：
- **默认**：把提纲和译名表中拿不准的条目给用户看，等用户确认或修改。用户要改，主会话直接编辑 `分析素材包.md` 里对应的提纲行。这是唯一的人工节点。
- **`--auto`**：不停，提纲留到最后的报告里。

## 第 3 步：逐章写作

1. 主会话运行 `python -P 根\tools\pack_chapter.py 根\素材\<slug>`。它会为每章生成 `chapters\NN.brief.md`，里面有本章提纲、候选金句、本章时间范围内的逐字稿、上一章结尾（上一章已写完时才有）和译名表。
2. 按上面的数量表派写作子 agent。多个子 agent 可以并行；并行时上一章结尾可能还没写出来，章节衔接留到第 4 步处理。

写作子 agent 模板：

```
你负责写一篇中文访谈长文的第 {NN}–{MM} 章。
先读这三个文件，严格执行：
- <技能目录>\interview-writing\SKILL.md
- <技能目录>\interview-writing\references\写作卡.md
- <技能目录>\writing-style\SKILL.md
每章的材料都在 {根}\素材\{slug}\chapters\NN.brief.md 里，读这一个文件就够，不要再去读 transcript.md 全文。
写法：先读完本章英文，想清楚每段在说什么，再照提纲的中文要点写；不逐句对照英文翻译。第 1 章前面加文章开头，最后一章后面加结尾。
写完保存为 chapters\NN.md，再运行：python -P {根}\tools\lint_zh.py chapters\NN.md
ERROR 必须改到 0；WARN 逐条处理（改，或在文件末尾的 HTML 注释里说明保留理由）。
回报：每章字数、lint 结果、你觉得写得最不顺的一处。
```

## 第 4 步：盲读挑刺与中文润色

### 4a 盲读挑刺

lint 只能抓能计数的问题，查不出"读着像翻译"。所以要让没看过英文的审读者读一遍，挑出最别扭的段落。

- **Codex**：主会话运行 `powershell -ExecutionPolicy Bypass -File 根\tools\blind_read.ps1 -Dir 根\素材\<slug>`。脚本为每章起一个独立的 `codex exec` 进程，结果写进 `盲读挑刺.json`。默认模型 `gpt-5.6-sol`，报"模型不支持"时用 `-Model` 换一个。
- **Claude Code**：按数量表派盲读子 agent，模板如下。

```
你负责盲读 {根}\素材\{slug}\chapters\ 下第 {NN}–{MM} 章的正文（NN.md）。
审读要求见 {根}\tools\blind_read_prompt.md（里面说正文在 <stdin> 块中，在这里指的就是这几个章节文件）。
只读这几个章节文件和这份提示词；不要读 brief、transcript、素材包或任何英文材料。
每章的结果写进 {根}\素材\{slug}\盲读\NN.json（JSON 数组，没有问题就写 []）。
回报：每章挑出几处。
```

想要第二意见时，两种方式可以都做：不同模型挑出的问题往往不重合。

### 4b 中文润色

按数量表派润色子 agent。润色者**不读英文**，只改表达，不增删信息。

```
你负责润色 {根}\素材\{slug}\chapters\ 下第 {NN}–{MM} 章（NN.md）。
先读：
- <技能目录>\interview-writing\references\写作卡.md
- <技能目录>\interview-writing\references\翻译腔对照表.md
- {根}\素材\{slug}\分析素材包.md 中的"原话清单"和"金句"两节（只读这两节）
- 盲读意见：{根}\素材\{slug}\盲读\NN.json 或 盲读挑刺.json 中本章的条目
不要读 brief、transcript 或任何英文材料。
每章依次：
1. 运行 python -P {根}\tools\lint_zh.py chapters\NN.md，处理 ERROR 和 WARN
2. 逐条判断盲读意见：合理的改；不合理的不改，写明理由。原话清单里受访者自己的比喻、例子和金句，只改措辞，不能删、不能换掉（以往审读者曾把受访者的原话比喻当成"AI 味"要求删除）
3. 读一遍全章，再改 lint 和盲读都没提到的问题：抽象主语、搭配不当、节奏单调、段落衔接生硬
4. 第 1 章的开头、最后一章的结尾必须精修：它们是编辑自己写的归纳，最容易写成套话
5. 和上一章的衔接：读上一章 NN.md 的最后一段，必要时调整本章开头的过渡
数字、人名、限定词、谁说的，一概不动。
每处改动记入 {根}\素材\{slug}\润色记录_NN.json：[{"chapter","step":"润色","before","after","reason"}]；不采纳的盲读意见也记一条，before 写原文，after 留空，reason 写不采纳的理由。
改完再跑一次 lint，ERROR 必须为 0。
回报：每章改了几处、不采纳几条盲读意见、lint 结果。
```

**`--deep-polish`**：润色子 agent 完成后，主会话把盲读挑出的段落连同开头、结尾交给 `adversarial-polish` 打磨，用快速模式（2 位评委，最多 2 轮）。批评者、改写者、综合者、评委都由主会话逐个派子 agent，每个角色只拿文件路径。任务描述：

```
这是一篇英文访谈的中文实录整理稿（第 NN 章）。读者是不看原视频、英文不一定好的中文读者。
目标：读起来像中文原创报道，没有翻译腔，节奏自然，问答清楚。
硬约束：①不得增删任何信息点、数字、人名、限定词；②不得软化或强化受访者的表态，不得对受访者作评价；
③争议、尖锐内容必须原样保留，不得以"冗长""敏感"为由建议删减；④编者注只补背景，不做价值判断；
⑤每章最多 2 条双语金句；⑥"原话清单"里受访者的比喻、例子和金句不得删除。风格依据 writing-style 技能和写作卡。
```

如果评委总是选删减最多的版本，就停用深度润色，并在复核说明里写明原因。

## 第 5 步：忠实与偏向核对（对照英文）

按数量表派核对子 agent：

```
你负责核对 {根}\素材\{slug}\chapters\ 下第 {NN}–{MM} 章，对照英文找出遗漏、走样和偏向。
先读：<技能目录>\interview-video\references\历史错误清单.md，以及项目根目录的 CLAUDE.md 或 AGENTS.md（偏向规则）。
每章读两样：正文 chapters\NN.md，以及写作材料 chapters\NN.brief.md（里面有本章的英文逐字稿）。
逐项检查：
- 完整性：brief 里本章时间范围内的每一段逐字稿，都登记进 {根}\素材\{slug}\核对\覆盖表_NN.csv，表头为：时间戳,章节,处理,说明。处理只能是"写入/合并/排除"；合并和排除必须写说明。排除只用于广告、寒暄、技术故障，不能以"太尖锐""有争议""不重要"为理由。brief 开头那段属于上一章，不用登记
- 细节：具体例子、数字、人名、典故有没有被概括掉；尤其警惕"这段太尖锐、太争议、差不多写到了"
- 走样：数字、限定词、说话人、语气强弱是否和原话一致；否定句、因果句逐句对照，防止意思译反
- 说话人：素材包里标了【说话人存疑】的地方逐一确认；受访者转述的别人的话，要和他本人的话分开
- 原话保留：润色中被删掉的受访者比喻、例子，找回来
- 偏向：措辞对等；没有评判性措辞；编者注只补背景，不能紧跟在受访者观点后面起反驳作用（起反驳作用的移到文末附注）
- 编造：lint 标出的"笑着说""停顿"之类，没有依据就删；转场提问必须有原话对应
发现问题直接改正文，改完重跑 python -P {根}\tools\lint_zh.py chapters\NN.md。
结论写进 核对\审查_NN.md：每章一节，逐项写"通过"或"已修订：位置和原因"。
回报：每章修订了几处、排除了哪些时间段。
```

全部核对完，主会话运行：

```
python -P 根\tools\coverage.py 根\素材\<slug>\transcript.md "根\素材\<slug>\核对\覆盖表_*.csv"
```

ERROR 必须为 0（漏登记的段落，派核对子 agent 补登）。排除超过全片 8%，或连续排除超过 3 分钟的，派子 agent 逐句复核。

## 第 6 步：配图（1 个子 agent）

```
你负责为 {根}\素材\{slug} 这期访谈配图。视频：{根}\素材\{slug}\video.mp4，正文：chapters\NN.md。
1. 粗筛：python -P {根}\tools\frames.py sheet video.mp4 sheets --start 0 --end <时长> --step 30，看全片缩略图拼板
2. 精筛：在候选时间点附近用 --step 3 再出局部拼板，确认最佳时刻
3. 选图规则：
   - 开场现场全景 1 张，要同时看得到主持人和嘉宾
   - 节目当场展示的屏幕材料优先（推文、图表、照片、地图、新闻画面）；同一事件有多个画面时，选最能体现事件分量的那张
   - 受访者特写最多 3 张，必须对应正文中的关键论述或情绪高点；谈沉重话题时，表情也要对得上
   - 不选闭眼、转场、模糊的画面；不凭表情推断心理；图注写的内容，画面上必须真有
   - 一般选 8–15 张。视频连线、全片单机位的访谈没有主持人画面和屏幕素材，这时每章选 1 张，开场图的图注交代采访形式
4. 写 配图计划.json：每项包含 seconds, file, chapter, anchor（正文里的一段原文，用来定位插图位置）, before, alt, caption（以"（原视频 HH:MM:SS）"结尾）, reason, visual_check
5. 取图：python -P {根}\tools\frames.py grab video.mp4 配图计划.json {根}\{slug}_访谈长文_assets
6. 逐张打开取出的原图核对：画面和图注、正文对得上，附近没有片尾卡或转场；结果写进 visual_check。对不上就换时间点重新取
回报：选了几张、各配在哪章、哪些规则没能满足及原因。
```

## 第 7 步：终稿

1. 主会话合并并插图：

```
python -P 根\tools\merge.py 根\素材\<slug> 根\<slug>_访谈长文.md
python -P 根\tools\frames.py insert 根\<slug>_访谈长文.md 根\素材\<slug>\配图计划.json
python -P 根\tools\report.py 根\素材\<slug>
```

2. 派 1 个终稿审查子 agent：

```
你负责一篇访谈长文的终稿审查：{根}\{slug}_访谈长文.md。
先读项目根目录的 CLAUDE.md 或 AGENTS.md，以及 <技能目录>\interview-video\references\历史错误清单.md。
1. 通读全文，按项目规则做一遍偏向审查：编者注、转场句、小标题有没有替读者下判断，有没有暗中贬低受访者
2. 核查编辑自己写的事实：开头、编者注、结尾里的每个日期、年龄、任期、"X 年前"、头衔；正文和编者注里的同一年份要一致
3. 写 {根}\素材\{slug}\文末附注.md，包含两节：
   - "## 文末附注"：事实核查和背景补充。受访者说法与公开资料有出入的，在这里说明，正文不插话
   - "## 复核说明"：数字来自 python -P {根}\tools\report.py {根}\素材\{slug} 的输出，以及 核对\审查_*.md；写明润色改了几处、盲读挑出几处、不采纳几条、核对修订几处、排除了多少分钟、配图几张、未解决项和推断之处
   最后附上原始视频链接
4. 需要改正文的，改 chapters\NN.md（不要直接改成稿，成稿会重新合并）
回报：改了什么、附注几条。
```

3. 主会话重新运行第 1 条的三个命令（成稿已存在时，`merge.py` 会把旧稿备份为 `.上一版.md`）。

4. **三道闸门**，全部通过才算完成：

```
python -P 根\tools\lint_zh.py 根\<slug>_访谈长文.md --full --json 根\素材\<slug>\lint.json
python -P 根\tools\coverage.py 根\素材\<slug>\transcript.md "根\素材\<slug>\核对\覆盖表_*.csv" --article 根\<slug>_访谈长文.md
```

- lint：ERROR 为 0（含开头和结尾的链接、复核说明），破折号每千字不超过 4 个
- coverage：ERROR 为 0；被标为偏薄的章节，派核对子 agent 逐段对照逐字稿
- 配图：`report.py` 显示"未核对 0 张"，`frames.py insert` 没有报"找不到锚点"

闸门不通过：把出错的行号和规则交给一个子 agent，让它改对应的章节文件，再从第 7 步第 3 条重来。

5. **向用户报告**，内容来自 `report.py` 和闸门输出：成稿路径、字数、配图数、三道闸门的结果、审查中修订的要点、改动最大的 5 处（改前和改后），方便用户几分钟内抽查润色方向。结论必须有数据支撑，不写"通篇没有其他问题"这类无法验证的话（过去这样说过，用户随后又找出一批问题）。`--auto` 跳过了提纲确认时，附上提纲和章节划分的理由。

## 脚本速查

用法都在这里，不要为了查用法去读脚本源码。

| 脚本 | 用法 | 作用 |
|---|---|---|
| `fetch.ps1` | `-Url <链接> -Slug <slug> [-SkipVideo] [-CookiesFrom chrome] [-Lang en]` | 下载元数据、字幕、720p 视频，生成 transcript.md |
| `pack_chapter.py` | `<素材目录> [章号 ...]` | 生成每章的写作材料 `chapters\NN.brief.md` |
| `lint_zh.py` | `<文件> [--full] [--json 输出] [--max N]` | 中文质量检查，有 ERROR 时退出码为 1 |
| `blind_read.ps1` | `-Dir <素材目录> [-Chapters 01,02] [-Model ...]` | 用 codex exec 逐章盲读（Codex 用） |
| `coverage.py` | `<transcript.md> <覆盖表...> [--article 成稿]` | 覆盖检查；可传多个表或通配符 |
| `frames.py` | `sheet <视频> <目录> --start --end --step` / `grab <视频> <计划> <assets>` / `insert <成稿> <计划>` | 缩略图拼板、取原帧、插图 |
| `merge.py` | `<素材目录> <成稿>` | 合并各章和文末附注 |
| `report.py` | `<素材目录> [--top 5]` | 汇总润色、盲读、配图记录，列出改动最大的几处 |
