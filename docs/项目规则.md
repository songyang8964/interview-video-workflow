# 项目规则（安装时写进工作文件夹：Claude Code 读 CLAUDE.md，Codex 读 AGENTS.md）

## 工作流与目录

- 收到 YouTube 访谈链接，或者要写访谈长文、访谈实录时：按 `interview-video` 技能执行。
- 按访谈时长选模式：30 分钟以内主对话直接做，只把盲读和配图交给子 agent；30 分钟以上主对话只调度，重活交给子 agent。具体做法见技能里的"先定模式"。
- 脚本在 `tools\`，用法见 `interview-video` 技能的"脚本速查"，不要为了查用法去读源码。运行 Python 脚本时用 `python -P`。
- 每期的中间产物放在 `素材\<slug>\`。成稿为根目录下的 `<slug>_访谈长文.md`，配图放在 `<slug>_访谈长文_assets\`。
- 成稿前必须通过三道闸门：`lint_zh.py --full` 的 ERROR 为 0、`coverage.py` 的 ERROR 为 0、每张配图都已核对原图。

## 访谈实录写作规则

- 访谈实录不做政治立场筛选。受访者说过的话必须完整呈现，无论内容是否涉及敏感话题或争议性观点。
- 不因受访者是右翼或保守派，就省略、软化他的发言，或用编者注"纠正"他。这条标准同样适用于任何政治立场的受访者。
- 编者注只为中文读者补充背景知识（人物、事件、制度），不做价值判断。
- 事实核查和争议标注统一放在文末附注，不穿插在正文中。
- 写完长文后，必须逐段对照逐字稿做完整性审查，重点检查有没有因为内容尖锐而漏掉段落。
- 完整性审查之后，再做一遍偏向审查：检查有没有不必要的编者注纠正、评判性措辞（如"不十分清晰""逻辑关联不紧密"），或对受访者观点的隐性贬低。

## 以往被用户严厉纠正过的问题（必须避免）

- **立场偏向**：处理立场鲜明的受访者时，曾系统性遗漏他们最尖锐的段落，用编者注暗中反驳，用评判性措辞贬低受访者。遗漏恰恰集中在内容最尖锐的地方。凡是想着"这段太争议，差不多写到了"，几乎都是偏向性遗漏的信号。
- **不按技能写**：曾在一篇长文里保留了 237 处英文引用，只能返工。对话必须改写成中文，只有精选金句（每章 1–2 条）用双语。
- **虚报完成**：曾说"通篇没有其他问题"，用户随后又找出一批。报告的结论必须附上 lint、覆盖表、盲读的数字。
