# interview-video-workflow

给一个 YouTube 英文访谈链接，得到一篇读起来像中文原创、配有原视频画面的访谈长文。

把英文访谈整理成中文，难的不是翻译，而是三件事同时做对：

- **不漏**：两三个小时的对话，最容易被悄悄略过的，恰恰是最尖锐、最有争议的那几段；
- **不歪**：数字、限定词、谁说的哪句话，一个都不能走样，编辑也不能借编者注替读者下判断；
- **好读**：读起来要像中文作者写的，没有"进行了讨论""这就是为什么"这类翻译腔，也没有满篇的破折号。

这套工作流由几个写作技能加一组检查脚本组成，可以在支持技能（Skills）的 AI 编程助手里运行，例如 Codex。能计数的规则由脚本把关，不能计数的写成清单，交给不同的人分步核对。

## 跑一次能得到什么

以一段 24 分钟的访谈为例（斯诺登谈手机监控）：

- 一篇约 6,500 字的中文长文，3 章，开头交代受访者和来源，结尾附原始链接；
- 3 张原视频截图，每张都核对过画面和图注是否一致，图注标明原视频时间；
- 文末附注：受访者说法与公开资料有出入的地方集中放在这里，正文不插话；
- 复核说明：润色改了多少处、盲读挑出几处、逐字稿有没有段落被略过；
- 一个素材目录，留着逐字稿、分析素材包、译名表、覆盖表、润色记录和审查记录，每处改动都能追溯。

这次的逐字稿共 31 段，31 段全部有着落。两轮盲读共挑出 29 处问题，逐条处理过，不采纳的也写明了理由。

## 快速开始

### 1. 准备环境

- Python 3.11+，以及 `pip install pillow numpy`
- [FFmpeg](https://ffmpeg.org/)
- [yt-dlp](https://github.com/yt-dlp/yt-dlp)：把 `yt-dlp.exe` 放进 `tools\`，或者加入 PATH
- [video-notes](https://github.com/songyang8964/video-notes)：截图要用它的取帧和画质检查模块
- 可选：对抗式打磨技能，`npx skills add jimliu/illustrated-agent-skills --skill adversarial-polish`

脚本按 Windows + PowerShell 编写。

### 2. 安装

1. 把 `skills/` 下的四个目录复制到 AI 助手的技能目录。Codex 的技能目录是 `%USERPROFILE%\.codex\skills\`。
2. 把技能文件里的 `<技能目录>` 换成实际路径。
3. 把 `tools/` 复制到你存放访谈长文的目录。
4. 把 `docs/项目规则.md` 的内容写进该目录的项目说明文件。Codex 读的是 `AGENTS.md`。

### 3. 使用

在 AI 助手里打开访谈长文目录，直接说：

```
用 interview-video 技能把这个访谈整理成中文长文：https://www.youtube.com/watch?v=xxxx
```

默认情况下，分析完会停一次，把提纲和译名表交给你确认，然后一路写完。常用的写法还有：

```
用 interview-video 技能处理：<链接> --auto                 全程不停，提纲附在最后的报告里
用 interview-video 技能处理：<链接> --deep-polish          问题段落改用对抗式打磨，更细，也更费额度
用 interview-video 技能处理：<链接> Guest_Show_123         指定素材目录和成稿的文件名
继续 interview-video 流程：素材\Guest_Show_123             中断后续跑，已完成的步骤会跳过
```

`--auto` 和 `--deep-polish` 不是程序参数，是写给 AI 看的开关，用中文说"全自动""深度润色"也一样有效。

## 它是怎么工作的

```mermaid
flowchart TD
    U["YouTube 链接"] --> F["下载<br/>字幕、元数据、720p 视频"]
    F --> T["逐字稿<br/>带时间戳，30–60 秒一段"]
    T --> A["分析<br/>素材包、提纲、译名表"]
    A --> P{"确认提纲<br/>（--auto 跳过）"}
    P --> W["逐章写作<br/>照中文要点写，英文只用来核对"]
    W --> L["中文润色<br/>脚本检查 → 盲读挑刺 → 段落精修"]
    L --> C["忠实核对<br/>逐段对照英文，登记覆盖表"]
    C --> I["配图<br/>缩略图拼板粗筛 → 取原帧 → 核对画面"]
    I --> G["三道闸门<br/>全部通过才算完成"]
```

每一步的产物都存在磁盘上。额度用完、窗口关了，换一个对话接着跑，已经完成的步骤会直接跳过。

## 几个设计取舍

### 忠实和好读，分开做

一边对着英文、一边用中文写，句子就会贴着英文的结构走，这是翻译腔的主要来源。所以写作、润色、核对拆成三步，每一步看的材料不同：

| 步骤 | 看什么 | 只管什么 |
|---|---|---|
| 写作 | 中文要点，英文只用来查数字、人名 | 把意思写全 |
| 润色 | 只看中文 | 读起来顺不顺 |
| 核对 | 中文对照英文 | 有没有漏、有没有走样 |

### 能数的，交给脚本

"不要翻译腔""不要遗漏"写在提示词里，模型未必照做，写长了还会忘。凡是能计数的规则，都写成了脚本：

- `lint_zh.py` 查禁用词、评判性措辞、翻译腔句式、破折号密度、长句、长引语、英文残留、口头禅、编造的神态动作（"笑着说""停顿了一下"）、正文里谈字幕和整理过程的句子、小标题是否只有话题没有结论；
- `coverage.py` 要求逐字稿的每一段都登记为"写入""合并"或"排除"，排除必须写明原因，而且不能以"太尖锐""有争议"为由。它还会算出每章"每分钟访谈写成多少字"，不到中位数一半的章节会被标为偏薄，这正是遗漏最常藏身的地方。

### 换一双没看过原文的眼睛

脚本查不出"读着像翻译"。所以每章交给一个只拿到中文正文的审读者，它看不到英文，也看不到润色记录，只负责挑出最拗口、最看不懂的几段。在 Codex 里，`blind_read.ps1` 会为每一章单独起一个进程，上下文完全隔离。换一个模型再读一遍，挑出的问题往往和第一轮不重合。

挑出的问题会逐条判断，不是照单全收。比如受访者自己用的比喻，审读者觉得"用力过猛"，也会保留原话，只改措辞。

### 规则是从返工里长出来的

[`历史错误清单`](skills/interview-video/references/历史错误清单.md)整理了此前 13 篇长文里被指出、导致返工的问题，例如：遇到立场鲜明的受访者，最尖锐的段落被整段跳过；编者注紧跟在受访者观点后面，暗中反驳；编辑自己写的开头把年份写错；配图的图注写着"颁勋章"，画面上却没有在颁奖。每一条都对应到流程里的一道检查，流程每次开工前也会先读这份清单。

## 三道闸门

成稿前必须全部通过：

| 闸门 | 检查 | 不通过的例子 |
|---|---|---|
| 中文检查 `lint_zh.py --full` | ERROR 为 0；破折号每千字不超过 4 个；开头和结尾有原始链接；文末有复核说明 | 正文出现"逻辑关联不紧密"这类评判；正文写了"这段在字幕中不完整" |
| 覆盖检查 `coverage.py --article` | 逐字稿每一段都有登记；排除要有理由；章节标题对得上 | 有两段没登记；连续排除超过 3 分钟 |
| 配图核对 | 每张图都打开原图核对过，插图位置找得到 | 截图漂到了片尾的订阅卡 |

WARN 级别的提示不阻止通过，但要逐条处理：改掉，或者写明为什么保留。

## 在 Codex 中使用

安装方式同上。和其他环境相比，有三处不同：

- **盲读挑刺**：运行 `tools\blind_read.ps1 -Dir 素材\<slug>`。脚本会先在 PATH 里找 codex，找不到就用 Codex 桌面版自带的 `%USERPROFILE%\.codex\.sandbox-bin\codex.exe`。默认模型是 `gpt-5.6-sol`，提示"模型不支持"时用 `-Model` 换一个。
- **并行写作**：环境支持子 agent 就分章并行写，不支持就逐章写，每章开写前重读写作卡。
- **下载要联网**：沙箱会请求批准。也可以先手动运行 `fetch.ps1`，流程会从分析那一步接着跑。

## 省额度的做法

- 下载、整理字幕、截图、画质判断、插图、格式检查都由脚本完成，不消耗模型；
- 逐字稿只在分析时通读一遍，之后各步按时间范围只读对应片段；
- 章节正文写在文件里，负责调度的对话不把全文读进上下文；
- 根据检查脚本给出的行号定点修改，不重写整章；
- 精修只针对盲读挑出的段落和开头、结尾，不整章重写；
- 看图先粗后细：先看全片每 30 秒一格的缩略图拼板，再在候选位置附近细看，最后只打开选中的原图。

## 局限

- YouTube 自动字幕没有说话人标注。谁说了哪句话，要靠上下文判断，拿不准的会标出来，留到核对时确认。
- 意思译反、说话人张冠李戴、编辑自己写错日期，这几类错误脚本查不出来，只能靠逐句对照逐字稿。流程里有这一步，但质量取决于执行的认真程度。
- 视频连线、全程单机位的访谈，可用的画面很少，通常每章只配一张。
- `--deep-polish` 依赖几个互相隔离的角色。环境不支持子 agent 时，效果会打折扣。

## 仓库结构

```
skills/
  interview-video/          总流程（入口）
    references/历史错误清单.md
  interview-analysis/       访谈分析：素材包、提纲、译名表
  interview-writing/        访谈实录写作
    references/写作卡.md          约 40 行的硬规则，每章开写前重读
    references/翻译腔对照表.md     英文结构、直译和自然中文的对照
  writing-style/            中文写作风格规范
tools/
  fetch.ps1                 下载元数据、字幕和视频，生成逐字稿
  transcript.py             json3 字幕 → 带时间戳的分段逐字稿
  lint_zh.py                中文质量检查
  coverage.py               逐字稿覆盖与章节密度检查
  frames.py                 缩略图拼板、取原帧、按锚点插图
  blind_read.ps1            盲读挑刺，每章一个独立的 codex exec 进程
  blind_read_prompt.md      盲读提示词
docs/
  项目规则.md               放进访谈长文目录的项目说明
```

## 脚本单独使用

```powershell
# 下载并生成逐字稿
powershell -ExecutionPolicy Bypass -File tools\fetch.ps1 -Url "<链接>" -Slug "Guest_Show_123"

# 中文质量检查（成稿加 --full）
python -P tools\lint_zh.py 文章.md --full --json lint.json

# 逐字稿覆盖检查
python -P tools\coverage.py 素材\<slug>\transcript.md 素材\<slug>\覆盖表.csv --article 文章.md

# 缩略图拼板、取原帧、插图
python -P tools\frames.py sheet  素材\<slug>\video.mp4 素材\<slug>\sheets --end 02:30:00 --step 30
python -P tools\frames.py grab   素材\<slug>\video.mp4 素材\<slug>\配图计划.json <slug>_访谈长文_assets
python -P tools\frames.py insert <slug>_访谈长文.md 素材\<slug>\配图计划.json

# 盲读挑刺
powershell -ExecutionPolicy Bypass -File tools\blind_read.ps1 -Dir 素材\<slug>
```
